# JRS_Imager 要件定義書

| 項目 | 内容 |
| --- | --- |
| プロジェクト名 | JRS_Imager |
| 版数 | 0.1（初版） |
| 作成日 | 2026-11-02 |
| 対象 | Real Ramen Simulator（以下「ゲーム」）のマイデザイン画像 |

---

## 1. 背景と目的

ゲームでは、ワールドごとの `Designs` フォルダにマイデザイン画像（PNG）が保存されている。
任意の画像をマイデザインとして使うには、画像を決まったサイズに整え、決まったファイル名で
決まったフォルダに置く必要があり、手作業では手間がかかりミスも起きやすい。

本サービスは **任意の画像を、選んだ形式とスロット番号に合わせて自動でリサイズ・リネームし、
ダウンロードできるようにする** ことを目的とする。
**本サービスの範囲はダウンロードまで** とし、ゲームフォルダへの置き換えとゲームへの反映確認は利用者が行う。
自分だけでなく友人も使えるよう、Web 上に公開する。

## 2. 現状調査（ゲームの保存形式）

調査対象パス（例）:

```
%LOCALAPPDATA%\RealRamenSimulator\Saved\SaveGames\MenWorlds\<SteamID>\Worlds\<WorldID>\Designs
```

```
Designs/
├── index.json          … デザインの割り当て情報（どの什器にどのデザインを貼るか）
├── MenuThumbnail/      … 512×512（本サービスの対象外）
├── Square/             … 512×512
├── Tall/               … 384×512
└── Wide/               … 512×384
    ├── 001.png  001.json
    ├── 002.png  002.json
    │   …
    └── 010.png  010.json
```

調査で分かったこと:

| # | 事実 | 要件への影響 |
| --- | --- | --- |
| F-1 | ファイル名は **3 桁ゼロ埋め**（`001.png` 〜 `010.png`）。 | 出力ファイル名は `001.png` 形式にする。 |
| F-2 | 各 PNG には同名の JSON（メタデータ）が対になっている。 | JSON は触らない（F-6）。 |
| F-3 | JSON の `PngSha256` は PNG 本体の SHA-256 と一致する。 | PNG を差し替えるとハッシュは食い違うが、問題ない（F-6）。 |
| F-4 | JSON には `bOccupied`（使用中か）、`bHasTransparency`（透過有無）、`DataHash`、`SlotIndex`（0 始まり）、`CanvasSize`（`Square512` / `Tall384x512` / `Wide512x384`）がある。 | JSON 生成を将来機能として検討する。 |
| F-5 | `Wide/004.png` が 384×512（縦長）になっており、JSON のハッシュとも一致しない。手作業による差し替えミスと思われる。 | **形式とサイズの取り違え防止** が実際に必要。 |
| F-6 | **PNG を置き換えるだけでゲームに反映される**（2026-11-02 利用者が確認済み）。 | 出力は PNG のみでよい。JSON の生成・更新は不要。 |

## 4. 機能要件

### 4.1 必須機能（MVP）

| ID | 機能 | 内容 |
| --- | --- | --- |
| FR-01 | 画像の読み込み | ファイル選択ダイアログ、またはドラッグ＆ドロップで画像を読み込む。対応形式は PNG / JPEG / WebP / GIF（静止画として 1 フレーム目）/ BMP。 |
| FR-02 | 形式の選択 | 「正方形（Square）」「縦長（Tall）」「横長（Wide）」から選ぶ。 |
| FR-03 | 形式の自動提案 | 読み込んだ画像の縦横比に最も近い形式を初期選択にする（利用者が変更可能）。 |
| FR-04 | スロット番号の選択 | 1〜10 から選ぶ。 |
| FR-05 | リサイズ | 選んだ形式のサイズに変換する。<br>Square: 512×512 / Tall: 384×512 / Wide: 512×384 |
| FR-06 | 合わせ方の選択 | 縦横比が合わないときの処理を選べる。<br>・**切り抜き（初期値）**: 枠いっぱいに拡大し、はみ出た部分を切る<br>・**全体を収める**: 画像全体を収め、余白を透明で埋める<br>・**引き伸ばし**: 縦横比を無視して枠に合わせる |
| FR-07 | プレビュー | 変換後の見た目を、出力サイズの枠付きで表示する。 |
| FR-08 | リネーム | 出力ファイル名を `NNN.png`（3 桁ゼロ埋め、例: 3 番 → `003.png`）にする。 |
| FR-09 | ダウンロード | 変換後の PNG をダウンロードする。 |
| FR-10 | 形式の表示 | ダウンロードボタンの近くに「縦長（Tall）用 003.png」のように、どの形式用のファイルかを表示する。 |

### 4.2 追加機能（MVP 後）

| ID | 機能 | 内容 |
| --- | --- | --- |
| FR-11 | まとめて変換 | 複数の画像を読み込み、それぞれに形式と番号を割り当てて ZIP で一括ダウンロードする。ZIP 内は `Square/001.png` のようにフォルダ構造を保つ。 |
| FR-12 | 位置・拡大率の調整 | 切り抜きのとき、画像をドラッグして位置を、スライダーで拡大率を調整できる。 |

## 5. 非機能要件

| ID | 区分 | 内容 |
| --- | --- | --- |
| NFR-01 | 公開 | インターネット上の URL から誰でも使える。インストール不要。 |
| NFR-02 | プライバシー | **画像はサーバーに送らず、すべてブラウザ内で処理する。** |
| NFR-03 | 費用 | 運用費は無料（静的ホスティングの無料枠）で収める。 |
| NFR-04 | 対応ブラウザ | Chrome / Edge / Firefox / Safari の最新版。 |
| NFR-05 | 対応端末 | PC を主対象とする。スマートフォンでも表示が崩れないこと。 |
| NFR-06 | 画質 | 縮小時にジャギーやモアレが目立たないこと。透過 PNG の透過を保つこと。 |
| NFR-07 | 性能 | 4000×4000 px 程度の画像でも 2 秒以内に変換できること。 |
| NFR-08 | 言語 | 画面表示は日本語。 |
| NFR-09 | 使いやすさ | 説明を読まなくても「画像を選ぶ → 形式と番号を選ぶ → ダウンロード」の 3 手順で使えること。 |
| NFR-10 | 保守 | ソースは Git（GitHub）で管理し、main への push で自動公開する。 |

## 6. 画面要件

1 画面構成とする。

1. 画像の読み込みエリア（ドラッグ＆ドロップ / ファイル選択）
2. 形式の選択（Square / Tall / Wide、サイズを併記）
3. スロット番号の選択（1〜10）
4. 合わせ方の選択（切り抜き / 全体を収める / 引き伸ばし）
5. プレビュー
6. ダウンロードボタンと形式の表示

## 7. 対象外

- ゲームフォルダへの置き換えと、ゲームへの反映確認（利用者が行う）
- ゲームフォルダの読み込み・書き込み（フォルダへの直接保存、現在のデザインの一覧表示など）
- MenuThumbnail フォルダの画像（将来検討）
- `index.json`（什器への割り当て）の編集
- 各スロットの JSON（`001.json` など）の生成・更新（PNG の置き換えだけで反映されるため不要）
- ゲームのセーブデータのバックアップ・復元
- 画像の編集機能（文字入れ、色調補正など）
- ユーザー登録、画像のサーバー保存

## 8. 前提・制約・確認事項

| # | 内容 | 状態 |
| --- | --- | --- |
| Q-1 | PNG だけ差し替えた場合（JSON の `PngSha256` と食い違う場合）に、ゲームが新しい画像を表示するか。 | **解決**: 反映される（F-6） |
| Q-2 | `DataHash` の計算方法。 | **解決**: JSON を扱わないため不要 |
| C-1 | 本サービスはゲームのファイルに触れない。ダウンロードした画像の置き換えは利用者の責任で行う。 | 前提 |
| C-2 | 本サービスはゲームの非公式ツールであり、公式とは無関係である旨を表示する。 | 前提 |
